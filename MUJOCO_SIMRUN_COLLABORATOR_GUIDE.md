# Reusable MuJoCo simulation-run contract

This is the handoff contract for collaborators who run a simulation that must
be replayable in MuJoCo, Blender, and Three.js. The physics result is saved
once as an immutable `.simrun`; renderers consume it later and must not
re-simulate the controller.

## 1. Required save procedure

Use `TrajectoryRecorder` from `codex/flysim_storage` and capture a sample after
each completed simulation step:

```python
from flysim_storage import TrajectoryRecorder

recorder = TrajectoryRecorder(
    physics,  # MjData, MjModel/MjData adapter, or dm_control physics
    metadata={
        "run_name": "my-fly-run-2026-08-27",
        "generator": "collaborator_script.py",
        "model_xml": str(model_xml),
        "model_xml_sha256": sha256_file(model_xml),
        "controller": "controller name/version",
        "controller_sha256": sha256_file(controller_file),
        "random_seed": 1234,
        "notes": "human-readable experiment description",
    },
)

for step in range(number_of_samples):
    apply_controller_and_step_mujoco()
    recorder.append()  # after mj_step; data.time is recorded automatically

recorder.save("H:/Projects/bosmos_deepspace/Data/Simulations/collaborator/my-run.simrun")
```

The ready-to-copy template is
`codex/scripts/save_mujoco_simrun_template.py`. It is intentionally explicit:
replace `run_simulation` with the collaborator's controller loop, but keep the
`recorder.append()` position and the metadata fields.

Run it with the pinned MuJoCo environment when using the default project setup:

```powershell
$py = 'E:/Projects/bosmos_deepspace/codex/experiments/steered_walk/.pixi/envs/default/python.exe'
$env:PYTHONPATH = 'E:/Projects/bosmos_deepspace/codex'
& $py E:/Projects/bosmos_deepspace/codex/scripts/save_mujoco_simrun_template.py `
  --model-xml E:/path/to/model.xml `
  --output H:/Projects/bosmos_deepspace/Data/Simulations/collaborator/my-run.simrun `
  --steps 1800 `
  --run-name my-fly-run-2026-08-27 `
  --controller collaborator-controller-v1
```

Never reuse an output directory. `TrajectoryRecorder.save()` rejects an
existing directory so the original states remain recoverable.

## 2. On-disk schema (version 1)

```text
<run-id>.simrun/
├── manifest.json
└── states.npz
```

`manifest.json` is UTF-8 JSON. `states.npz` is a compressed NumPy archive.
Arrays are stored as float64 and have first dimension `sample_count`:

| Array | Required | Shape | Meaning |
|---|---:|---|---|
| `time` | yes | `[N]` | MuJoCo `data.time`, monotonic seconds |
| `qpos` | yes | `[N, nq]` | Generalized positions; authoritative replay state |
| `qvel` | no | `[N, nv]` | Generalized velocities |
| `act` | no | `[N, na]` | Actuator/internal activation state |
| `ctrl` | no | `[N, nu]` | Applied actuator controls |
| `mocap_pos` | no | `[N, nmocap, 3]` | Mocap positions, when present |
| `mocap_quat` | no | `[N, nmocap, 4]` | MuJoCo WXYZ mocap quaternions |
| `userdata` | no | `[N, nuserdata]` | User state, when present |

The manifest must contain:

```json
{
  "schema": "bosmos.mujoco-trajectory",
  "schema_version": 1,
  "created_utc": "ISO-8601 timestamp",
  "data_file": "states.npz",
  "data_sha256": "sha256 of states.npz",
  "trajectory": {
    "sample_count": 1800,
    "start_time_seconds": 0.0,
    "end_time_seconds": 59.966,
    "duration_seconds": 59.966,
    "nominal_sample_timestep_seconds": 0.03333333333333333,
    "arrays": {"time": {"dtype": "float64", "shape": [1800]}},
    "replay_basis": "qpos + MuJoCo forward kinematics",
    "quaternion_convention": "MuJoCo WXYZ where present in qpos/mocap_quat"
  },
  "model": {
    "kinematic_sha256": "generated by model_signature(model)",
    "dimensions": {"nq": 0, "nv": 0, "na": 0, "nu": 0, "nbody": 0, "njnt": 0},
    "names": {"bodies": [], "joints": [], "actuators": []}
  },
  "provenance": {}
}
```

The recorder fills the exact dimensions, names, array shapes, checksum, and
model signature automatically. Do not hand-edit those generated fields.

## 3. Validation before handoff

```powershell
$env:PYTHONPATH = 'E:/Projects/bosmos_deepspace/codex'
& $py -m flysim_storage H:/Projects/bosmos_deepspace/Data/Simulations/collaborator/my-run.simrun
```

The loader verifies the schema, required arrays, shapes, monotonic timestamps,
and `data_sha256`. A renderer must additionally load the same model and reject
the run if `model.kinematic_sha256` differs.

## 4. Conversion for the three renderers

The `.simrun` remains the authority. To make a browser/Blender recording:

1. Load the run with `TrajectoryRun.load(path, verify_checksum=True)`.
2. Apply each exact `qpos` sample to a matching MuJoCo model and call
   `mujoco.mj_forward`.
3. Export calibrated FlyBody joint transforms as
   `bosmos.interchangeable-mujoco-replay` schema version 2.
4. Keep `interchange.simrunId`, `interchange.simrunDataSha256`, model identity,
   sample count, and source duration in the derived recording.
5. Blender and Three.js consume the derived frame sequence; they do not run
   the controller or invent a new command schedule.

The existing conversion entry point is
`codex/scripts/create_interchangeable_banc_replay.py`; the full renderer
contract is in `MUJOCO_INTERCHANGE_REPLAY_SCHEMA.md`.

## 5. Reproducibility checklist

- Preserve the exact `.simrun` directory unchanged.
- Record model XML path and SHA-256, controller/version and SHA-256, seed,
  package/environment versions, and experiment parameters in `provenance`.
- Capture `qpos` after stepping, not before, and keep timestamps monotonic.
- Use a new run ID for every experiment; never overwrite a prior run.
- Share `manifest.json` and `states.npz` together; the checksum binds them.
- Treat rendered MP4s, PNGs, Blender files, and browser JSON as derived outputs.
